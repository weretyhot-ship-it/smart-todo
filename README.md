# smart-todo · 智能待办清单

把中文大白话拆成结构化待办的小工具。你写「明天下午三点交论文，很重要；顺便买牛奶」，
它会输出带 **任务名 / 时间 / 优先级 / 类别** 的待办卡片，并按优先级排好、到点提醒。

## 它做什么

- **大白话 → 结构化任务**：调用大模型，把一句话拆成多条待办，自动推断时间、优先级、类别
- **模糊时间会算**：把当前时间注入提示词，「上午 / 下午 / 明天 / 下周一」都会被换算成具体时刻
- **到点提醒**：页面内提醒卡 + 系统通知（Notification API，静音）；提醒卡上可直接「标记完成 / 10 分钟后再提醒」
- **没有模型也能用**：内置离线解析器（正则），不填 API Key、断网、模型超时都能兜底
- **数据本地持久化**：所有任务存在 localStorage，接口地址与模型可自行配置

## 快速开始

**方式一：本地服务（推荐，系统通知需要它）**

```bash
python launcher.pyw          # 起本地服务并自动打开浏览器
```

然后访问 <http://localhost:8000/index.html>。

> 为什么需要本地服务：`Notification` API 只在**安全来源**（https 或 localhost）可用，
> 直接双击 `.html` 的 `file://` 方式浏览器会**静默拒绝**通知。`launcher.pyw` 就是为了绕开这一点。

**方式二：直接打开**

双击 `index.html` 即可使用（除了系统通知，其它功能都正常）。

**然后**

1. 点右上角「设置」，填入 [DeepSeek](https://platform.deepseek.com/) 的 API Key（只存在本机浏览器）
2. 在左侧输入框写一句话，点「智能拆解」
3. 没有 Key 也能先玩：点「离线解析」，或点卡片里的「填入示例数据」

Windows 用户还可以运行一次 `pythonw make-shortcut.pyw`，在桌面生成一个带图标的快捷方式（自动创建图标）。

## 技术结构

```
index.html        页面骨架：元素与 id，不含任何逻辑
styles.css        全部外观：布局、玻璃卡片、优先级视觉
ui.js             全部业务逻辑：调模型 → 解析 JSON → 归一化 → 排序 → 渲染 → 持久化 → 提醒
glass-card.js     只做一件事：每帧把背景视频复制到画布，让玻璃卡"折射"它
launcher.pyw      起本地静态服务并打开页面（为了 Notification 的安全来源要求）
make-shortcut.pyw 在桌面生成带图标的快捷方式（Windows，可选）
assets/           图标等静态素材
tools/verify.mjs  验证脚本（见下文）
docs/             README 用到的截图
```

数据流只有一条：

```
输入框 → buildSystemPrompt() 注入当前时间与解析规则
       → fetch DeepSeek（JSON 模式）
       → extractJson() 抠出 JSON（容忍 markdown 代码块 / 纯数组）
       → normTask() 归一化每条任务（时间统一成 ISO、优先级收敛成 high|mid|low）
       → localStorage → sortTasks() → render() 画卡片
       → checkDue() 每 10 秒检查到点 → 系统通知 + 页面内提醒卡
```

## 四个技术决定（也是这个项目最值得看的部分）

**1. 两个脚本共享全局作用域，撞了 `const` 让整个文件不执行**

`ui.js` 和 `glass-card.js` 都是普通 `<script>`，共享同一个全局作用域，且各自声明了 `const video`。
结果是 `ui.js` 整个文件抛出 SyntaxError、一行都不执行，表现却是"所有按钮都没反应"——很容易误判成事件绑定问题。
两个文件现在各自用 IIFE 包裹隔离作用域；`tools/verify.mjs` 会把它们装进同一个上下文加载，一旦再次撞名立刻报错。

**2. Notification 只在安全来源可用，且失败是静默的**

`file://` 打开时通知永远不弹、也不报错。处理方式是：`launcher.pyw` 提供 `http://localhost` 这个安全来源，
同时页面内准备了**兜底提醒卡**（带完成/稍后提醒按钮 + Web Audio 提示音），并有一段诊断文案直接告诉用户
问题出在协议、浏览器权限还是 Windows 通知设置上。

**3. 模型输出不可靠，所以在边界上做归一化**

提示词要求"只输出 JSON"，但仍会收到带 markdown 代码块、纯数组、时间格式不一致、优先级写成中文的情况。
`extractJson()` 负责抠出 JSON，`normTask()` / `normPriority()` 负责把字段收敛成统一格式，
都失败时落到本地正则解析器。**不确定性被挡在边界之外，卡片拿到的永远是干净数据。**

**4. 用脚本验证，而不是靠刷新页面肉眼检查**

见下节。

## 验证

```bash
node tools/verify.mjs      # 等价于 npm test，零依赖
```

它把页面按**网页真实的方式**加载：读出 `index.html` 里的元素、模拟最小 DOM、把两个脚本装进同一个
全局上下文执行，然后跑 53 项检查——覆盖语法冲突、旧数据继承、优先级排序、时间与时区、
勾选/删除、到点提醒链路、通知降级、离线解析、示例数据等。

> 这个脚本不是装饰：上面第 1 条那个"按钮全失灵"的 bug，就是在它这里被复现并定位到行的。

## 已知限制

- API Key 存在浏览器 localStorage，请求由前端直接发出 —— 这是 **BYOK（自带 Key）** 的取舍：
  为了保持"单文件可双击运行"，没有引入服务端代理。生产环境应由服务端持有密钥。
- 直接以 `file://` 打开时无法使用系统通知（浏览器限制），页面内提醒卡仍然工作。
- 背景视频引用第三方 CDN 资源，断网或对方下线时只剩纯色背景。
- 数据只在本机浏览器，没有账号、没有多端同步。
- 浏览器清除站点数据会连任务一起清掉。
